| 步 | Skill | 职责 | 关键设计 | 成熟度 |
|---|---|---|---|---|
| 1️⃣ | iskill-hot-topic-scout | 每日热点选题 | 画像三维打分 → Top10+Top3 选题卡 | ✅ 已实测（农场画像跑通） |
| 2️⃣ | iskill-viral-teardown | 爆款视频拆解 | 五维拆解；复用 media-transcribe | ✅ 依赖链打通 |

| Skill | 被谁复用 | 说明 |
|---|---|---|
| iskill-media-transcribe | 2️⃣拆解、6️⃣配音对齐 | 下载+Whisper 转写，视频号 cookie 走 `~/.iskill-weixin-cookies.txt` |
| iskill-dig-media | 6️⃣零素材出片 | Pixabay API 挖素材，key 走 `~/.iskill-dig-media.json` |

### 数据流（文件即接口）

```
hot-topic.profile.md（画像，一次配置）
   ↓
选题/YYYY-MM-DD-选题.md → 拆解/*-拆解.md → 文案/*-口播稿.md
   → 文案/*-口播稿-v2.md（预检放行）→ 成片/*.mp4（或剪映草稿）
旁路：dig-media/<关键词>/（网络素材）+ raw/（自家实拍，优先）
```

### 已固化的工程约定
- 每个 skill 独立 git 仓库（ISkills/）+ `~/.workbuddy/skills/` 软链；**均未推 GitHub**
- 配置解藕：key/cookie 一律 `~/.iskill-*`，不绑死 agent 目录
- 接单契约：预检不放行，剪辑不接单；字幕唯一来源 = v2 定稿
- 实锤沉淀：Homebrew ffmpeg 缺 drawtext（用 imageio 构建）、长句手动断行、cookie 勿放 /tmp

### 待补短板
1. 未推 GitHub（专家化前建议先固化远端）
2. 配音/BGM/LOGO 未进样片；剪映草稿引擎（Phase 7）未实测
3. 只跑通 1 条全链路（农场赛道），泛化性未验证

## 二、市场查重结论（先查再建）

搜了推荐市场，最接近的三个：
- **内容创作专家团**（AiContentCreatorTeam）：多模态内容生产，但偏品牌广告创意，无「选题→拆解→预检→成片」流水线，无本地剪辑执行
- **爆款炼金师**（ViralTopicMaster）：只覆盖选题/文案环节
- **斗音音**（DouyinStrategist）：抖音策略咨询型，无工具执行

**结论：无人覆盖我们的六步全链路 + 本地工具执行能力，值得自建。差异化卖点=不只是给建议，而是真能出片。**

## 三、专家化方案：Team 型「爆款短视频操盘团」

### 为什么选 Team 型（而非单 Agent）
六步天然是流水线分工，各步有独立的触发词、质量标准和否决权（预检可打回）。Team 型能把 SOP 写进主理人编排，团员各司其职，还能让预检「独立质检」不被文案角色自带立场带偏。单 Agent 也能跑（六步就是一段流程），但展示和协作体验差一档。

### 专家包结构（资料转化模式）

```
viral-video-team/
├── .workbuddy-plugin/plugin.json   # name: viral-video-team, expertType: team, categoryId: 06-ContentCreative
├── agents/
│   ├── viral-video-team-lead.md    # 主理人「操盘手」：SOP 六步编排 + 需求收集 + 调度
│   ├── topic-scout.md              # 选题侦察兵 ← iskill-hot-topic-scout
│   ├── teardown-analyst.md         # 拆解分析师 ← iskill-viral-teardown
│   ├── copywriter.md               # 爆款文案手 ← iskill-viral-copywriter
│   ├── audience-proxy.md           # 观众代言人 ← iskill-copy-deslop
│   ├── compliance-checker.md       # 合规质检员 ← iskill-content-precheck（有打回权）
│   └── clipper.md                  # 剪辑师 ← iskill-video-clipper + iskill-dig-media
├── skills/                          # 打包 8 个 SKILL.md + references/（违禁词底表、画像模板）
├── bin/                             # dig_media.mjs 等通用 CLI
└── avatars/                         # 7 张统一风格头像（ImageGen 生成）
```

### 内容转化映射（按 expert-manager 转化策略）

| 现有资产 | 转化为 |
|---|---|
| 各 SKILL.md 的角色定位与触发词 | 对应团员 MD 的「角色定义 + 触发场景」 |
| 各 SKILL.md 的工作流程/Phase | 团员 MD 的「工作流程」章节 |
| 违禁词底表、画像模板 | skills/*/references/ + templates/ |
| dig_media.mjs、transcribe 脚本 | bin/ + skills/*/scripts/ |
| 数据流文件约定（选题/拆解/文案/成片） | 主理人 MD 的 SOP 章节（每步产物路径） |
| 实锤坑（ffmpeg 构建、cookie、断行） | 对应团员 MD 的「避坑」章节 |
| quickPrompts | 「帮我选题」「拆这条视频」「出成片」等 |

### 执行步骤（串行，每步不可跳）

1. **前置固化**：8 个 skill 仓库推 GitHub（iskill-github-publisher，隐私身份），保证专家包引用的 skill 有唯一直源
2. **决策确认**：和你确认 Team 成员粒度（6 团员 or 压缩成 4：选题+拆解合并、deslop+precheck 合并）
3. **初始化**：`init_expert.py viral-video-team --type team` 到专家目录 `~/.workbuddy/plugins/marketplaces/my-experts/plugins`
4. **填内容**：按上表把 8 个 SKILL.md 转写成 7 份 agents MD（displayDescription 中文 40-50 字、tags/quickPrompts 各固定 3 个、主理人文件名带团队前缀）
5. **头像**：ImageGen 生成 7 张统一风格头像 → avatars/
6. **校验**：`validate_expert.py`（禁 [TODO] 残留）
7. **注册**：`register_expert.py` 写入 marketplace.json
8. **打包**：`package_expert.py` 产出可分享包
9. **实测**：在专家中心发起对话跑一轮六步，回归验证（含预检打回路径）

### ⚠️ 可移植性风险（专家给其他人用时）

| 本地依赖 | 缺失时的降级路径（须写进团员 MD） |
|---|---|
| imageio-ffmpeg 构建（drawtext） | 无字幕版出片 / 引导安装 |
| 视频号元宝 cookie | 拆解限本地文件或用户自传视频 |
| Pixabay key | 素材退回用户目录，无则明确说明卡点 |
| VoiceBox/whisper | 字幕退回估时分段，提示可自录配音 |
| jianying-editor | 剪映草稿功能降级为纯 ffmpeg 成片 |

**设计原则：每一步都「尽力而为、明确卡点」，绝不静默跳过或硬拼。**
